# Windows 图形组件兼容性排查方案

## 背景和证据

Issue #302 报告 Windows 客户端退出串流时在 NVIDIA 组件内部崩溃。上游 issue #1788 出现了相近的 `NvPresent64` / `nvcuda64` 调用栈。现有证据尚不能证明 Smooth Motion 或某个 DLL 是根因，也不能证明客户端窗口恢复与驱动内部资源释放存在特定竞态。

当前正常退出路径已经在恢复主界面前删除视频解码器和 SDL 串流窗口；不引入未经验证的延时或强制同步。保持所有 NVIDIA 功能的默认行为。

## 实验方案

在 Windows 现有 AntiHooking 中增加进程级、显式启用的 `MOONLIGHT_BLOCK_DLLS` 环境变量，以分号分隔需要阻止的 DLL 基名，例如 `NvPresent64.dll;nvspcap64.dll`。比较不区分大小写，只支持完整的 `.dll` 基名，不支持路径或通配符。现有内置黑名单不受影响；环境变量未设置时行为不变。配置在启动时生效，修改后需要重启 Moonlight。

该开关用于对照实验，不是确定性的修复。现有拦截器仅覆盖安装钩子之后经过 LoadLibrary/LoadLibraryEx 的加载；静态导入、加载器内部加载、已加载的模块或其他注入方式可能绕过。被阻止模块依赖关系可能导致相关驱动功能不可用，也可能使应用无法启动。不要默认屏蔽 NVIDIA 驱动、CUDA 或其他图形 DLL。

## 验证

1. 检验名称匹配、路径提取、大小写、空白、多个条目、非法条目、内置黑名单及未配置时的原有行为。
2. Windows x64 编译、仓库格式检查与相应测试通过；PR CI 覆盖平台构建。
3. 报告者使用相同配置分别运行无开关、有开关两组，重复串流退出；确认目标模块是否真正未加载，记录新日志和结果。目标模块仍加载时不能把实验结果当作已拦截。
4. 若实验有效，再单独研究触发条件和可安全默认启用的处理；若无效，继续用匹配时间的日志和 dump 分析。
