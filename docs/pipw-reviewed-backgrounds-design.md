# Pipw 背景审核过滤设计

## 目标

参考 Android PR [#696](https://github.com/qiin2333/moonlight-vplus/pull/696)，在 Qt 客户端下载 Pipw 背景后、解码和显示前核对实际图片字节的 MD5。使用该 PR 提供的同一份 PC/Phone 审核表，继续请求 https://img-api.pipw.top；用户自定义 API 指向此主机时也进入审核流程。

默认内置二次元背景使用 PC 图池；官方自定义地址带 phone=true 时使用 Phone 图池。Qt 保留现有明确的背景来源选择，不新增设置。

审核表来自 moonlight-vplus 的 d83e8223052491180467fb2b7a06443a6286b7cf 提交，PC 382 条、Phone 674 条，与 Android 端使用同一份数据。

## 请求与过滤

1. 审核表作为 Qt resource 打包，严格检查两组记录的文件名、摘要和重复 ID；重复摘要别名保留，一个摘要只取一个稳定兜底文件名。
2. Pipw 仅接受 HTTPS、无用户凭据和 fragment 的 URL。一次刷新只请求一次随机 API，要求返回重定向；手动解析后续重定向，允许 CDN、目录和文件名变化，但验证路径、图片后缀和图池。
3. 图片逐块下载到上限为 20 MiB 的内存缓冲区，并增量计算 MD5。每个请求显式计时，API 7 秒、每次候选下载合计 15 秒、整轮 30 秒，另设 5 秒传输空闲超时；空内容、截断内容、非 identity 编码和未知摘要拒绝。Qt 使用异步网络回调，替代 Android 的阻塞请求与临时下载文件。
4. 对实际下载字节计算 MD5，命中所选图池的审核表后才允许进入图片解码。文件名和 ETag 不作为审核证明。
5. 随机图片失败后，最多在已取得的合法 CDN 路径上尝试一张审核图片：替换最后一个路径段，去掉查询参数。不再次抽取随机 API。
6. 明确取消、切换来源、刷新或页面销毁时，过期结果不得更新当前页面。摄影和普通自定义 API 保持现有加载策略。

## 缓存、显示与导出

- 新缓存目录使用 CacheLocation/vplus-backgrounds。Pipw 缓存身份增加审核版本，禁止复用旧的未经审核背景缓存。
- Pipw 在当前进程内共享已校验图片与显示预览；主页面同步到窗口的现有背景 URL 机制保持使用同一张图片。
- 原始已审核字节与 JPEG 显示预览同时保留。JPEG 预览解决平台图片格式差异；导出 Pipw 时使用原始字节，并再次核对 MD5。
- Pipw 原图与预览按实例管理，刷新和销毁只清理自身创建的文件，避免另一实例的显示和保存受到影响。
- 保存对话框打开时固定已审核原图的字节快照；刷新或切换来源不改变待保存内容。保存或取消后释放快照，文件后缀根据原始字节格式确定。
- Pipw 刷新或加载失败时不保留上一张图片作为兜底，使用现有内置背景。已失效的下载不得重新显示。
- 保存对话框默认打开 Pictures/vplus，默认文件名 vplus-background-时间戳，继续允许用户选择其他目录。创建目录失败则报告错误。用户历史保存文件不迁移、不删除。

## 实现划分

- pipwbackground：审核表解析、URL 策略和受限异步下载。
- ImageUtils：识别官方 Pipw 地址、取消任务、已审核原图/预览管理和导出。
- PcView.qml：审核缓存身份、刷新/切换时清理旧图、接入错误和忙碌状态、默认保存目录。
- resources.qrc / app.pro：打包审核表和编译新文件。

## 验证

编译 Qt/C++ 和 QML 验证调用与资源集成。人工验收覆盖成功显示、未知摘要拒绝后兜底、快速切换来源、刷新、保存对话框期间刷新、取消保存和两个实例独立使用背景。

MD5 用于与已审核内容逐字节核对，不是在线内容识别或恶意碰撞防护。未知内容（包括重新编码后的图片）不会直接放行。

## 当前验证结果

- ImageUtils、PipwBackgroundDownloader、PcView 的 QML 预编译对象和完整资源对象在 Windows Release 配置下编译通过。
- 已移除 D3D11 渲染器未使用的 atlbase.h 引用，并补齐 USB 服务接口所需的 advapi32.lib；完整 Windows x64 Release 构建通过，已生成便携 ZIP 和 MSI。
- 便携版已完成本机解压部署，程序 SHA256 与构建输出一致；Windows 后端启动检查确认主 QML、中文翻译和 SDL 初始化成功。
- Qt 5.12 使用显式空闲定时器，Qt 5.15 及以上使用请求传输超时；API、候选和整体请求预算均由显式定时器限制。Qt 5.12 与 macOS/Linux 的最终构建和真实界面仍需对应环境验证。
